# M8 PR1 Phase A: Products and Events backend contract

This is the authoritative implemented Product/Event Admin API contract, superseding the historical write examples in API_SPEC. Products and Events UI remains deferred. No deployment, remote Sheet operations, credentials/configuration changes, commit, or push is part of this work.

## Implementation decisions

- Keep `adminGetProducts`, `createProduct`, `updateProduct`, `deleteProduct` and their Event counterparts. Add `adminGetProductDetail` and `adminGetEventDetail`.
- All actions use protected POST JSON `{action, token, payload}`. Four canonical Admin roles can read; only `editor` and `super_admin` can mutate. Authenticate again after acquiring the script lock.
- Create accepts editable fields and creates draft only. IDs are generated by the server. Update accepts the entity ID, `expected_revision`, and one or more editable fields and/or status. Delete accepts only ID and expected revision.
- Domain validation is explicit. Events use the existing single `event_date`, not invented start/end-date columns. Products use `price_range` text. No schema extensions or draft/version tables.
- Content hashes cover identity, status, and all editable columns in a fixed order. Timestamps are excluded. Compare under the script lock; return `CONFLICT` on stale content.
- Write one complete row with one `setValues`, preserving unrelated columns and verifying the complete row. Preflight unique required headers, destination, formats, and absence of formulas. Nonempty string destinations require `@`; booleans require `0` or `0.###############`, the formats proven by the M7 disposable Sheets probe. Rows with formulas or formula-like legacy text fail preflight rather than being rewritten. No request changes formats/schema. Read back after flush, then append and verify a canonical audit. Unverified write attempts return `OUTCOME_UNKNOWN` with identity. A verified entity with failed audit returns success with `audit_status: "unconfirmed"`; never retry the mutation to repair audit.
- Public cache generations live in Script Cache, not Script Properties. Remove and verify removal of the content generation under lock before mutation. Public readers initialize a missing generation under the same lock, or bypass caching while it is held. Eviction generates a fresh namespace, never a reusable default. Product/Event lists/details, Home, and Search include this generation. Existing Place epochs remain intact.

## Lifecycle

| From | Permitted destinations |
|---|---|
| draft | published, archived, deleted |
| published | hidden, archived, deleted |
| hidden | draft, published, archived, deleted |
| archived | draft, deleted |
| deleted | draft |

Same-state status assignments are rejected. Content edits are allowed in draft, published, and hidden only. Restore is a status-only update to draft. Archive/delete retain all content. Publishing validates the complete record and its Place reference. A related Place must exist uniquely and be draft or published; publishing requires a published Place. Removing an existing invalid reference is allowed through an edit.

Combining content edits with transitions to draft, archived, or deleted is rejected. Publishing/hiding may include edits with complete prospective-record validation. Status-only retirement/restoration can retain old content whose Place is unavailable. Public readers expose only published records; Events additionally require a valid event date. There is no separate published snapshot: editing published content immediately changes public output.

## Actions and authorization

| Products | Events | Payload |
|---|---|---|
| `adminGetProducts` | `adminGetEvents` | List filters; `{}` is valid |
| `adminGetProductDetail` | `adminGetEventDetail` | Exactly `{product_id}` / `{event_id}` |
| `createProduct` | `createEvent` | Editable fields only; server creates draft |
| `updateProduct` | `updateEvent` | ID, `expected_revision`, at least one editable field or `status` |
| `deleteProduct` | `deleteEvent` | Exactly ID and `expected_revision`; soft-delete |

| Role | List/detail | All mutations |
|---|---|---|
| viewer | yes | no |
| reviewer | yes | no |
| editor | yes | yes |
| super_admin | yes | yes |
| missing/invalid/expired/revoked/inactive session | no | no |

All actions are literal Router POST branches using JSON `{action, token, payload}`. Query action/token never substitute for the body. No protected GET, dynamic dispatch, diagnostics, client-role authority, retries, or force-write option. AuthService is unchanged and runs before lock acquisition and again under lock for writes.

List accepts only `keyword` (text, max 200 characters), `status` (empty or stored status), `page` (integer 1–1,000,000, default 1), `page_size` (integer 1–100, default 20), plus `category` for Products or `event_type` for Events (empty or domain enum). Keyword matches identity and Thai/English name/title case-insensitively. Lists include every status by default in source-row order and return `items`, `total`, `page`, `page_size`, `total_pages`.

## Editable payloads

Create requires the fields marked required below. Optional fields default to `""`, except `is_featured` defaults to `false`. Content patches are merged with the stored record under lock and completely validated; omitted fields remain unchanged. Publishing also validates complete content. Status-only retirement/restoration retains stored content without requiring domain/reference revalidation. `null` is invalid. Create rejects caller-supplied ID/status/timestamps. Update ID selects the target and is not editable. Server-managed timestamps, revision, unknown keys, and client role/permission fields are rejected as editable data.

| Product fields | Contract |
|---|---|
| `name_th`, `description_th` | Required nonempty text |
| `category` | Required: `food`, `souvenir`, `herbal`, `honey`, `handicraft`, `fruit`, `community_activity`, `tourism_service`, `accommodation`, `transport` |
| `name_en`, `producer_name`, `description_en`, `price_range`, `phone` | Optional text; price is display text |
| `district` | Empty or `ban_ta_khun`, `khiri_rat_nikhom`, `phanom` |
| `related_place_id` | Empty or unique available Place ID |
| `contact_url`, `google_maps_url`, `image_url` | Empty or absolute validated HTTP(S) URL |
| `latitude`, `longitude` | Both empty or finite JSON numbers, latitude −90…90, longitude −180…180 |
| `tags` | Empty or pipe-separated unique nonempty text items; max 100 items, 200 characters each |
| `is_featured` | JSON boolean only |
| `sort_order` | Empty or nonnegative safe integer |

| Event fields | Contract |
|---|---|
| `title_th`, `location_th`, `description_th` | Required nonempty text |
| `event_type` | Required: `launch`, `festival`, `community_market`, `learning`, `seasonal`, `otop`, `tourism`, `other` |
| `event_date` | Required real Gregorian `YYYY-MM-DD`, year 0001–9999, with leap-year validation |
| `start_time`, `end_time` | Empty or `HH:mm` (00:00–23:59). End requires start and must be strictly later that day. Start alone is allowed |
| `title_en`, `location_en`, `description_en`, `contact_name`, `contact_phone` | Optional text |
| `related_place_id` | Empty or unique available Place ID |
| `image_url`, `register_url`, `google_maps_url` | Empty or absolute validated HTTP(S) URL |
| `latitude`, `longitude` | Same paired-number rule as Products |
| `is_featured` | JSON boolean only |

Stored Boolean boundary: `AdminContentService_table_` canonicalizes exactly stored `is_featured: ""` to Boolean `false` in its in-memory row snapshot for both domains, before detail/list projection, revision generation and mutation merging. Stored blank and stored false therefore share a revision. Reads never rewrite Sheets or migrate rows. Partial edits and publishing can persist canonical false through the normal verified write path. Existing true/false retain their meaning; no other malformed stored value is repaired. Explicit request values remain strict JSON booleans: `""`, `"false"`, `0`, `1` and `null` are rejected. Public blank-as-false behavior is unchanged.

Text is trimmed, max 20,000 UTF-16 code units, and rejects malformed Unicode, unsafe controls, and leading `=`, `+`, `-`, `@`, or apostrophe after whitespace. This also rejects formula-like phone/display-text prefixes; Phase B must surface validation instead of silently stripping them. URLs are max 2,048 characters with an ASCII dotted host and optional decimal port 1–65535. DNS labels retain the existing alphanumeric/hyphen syntax (no leading/trailing hyphen), and the terminal label must begin with an ASCII letter. Numeric hosts must be canonical IPv4: exactly four decimal octets 0–255, with no leading zeros except a single zero. Abbreviated, octal, hexadecimal and other numeric-terminal host forms, including `999.999.999.999` and `example.123`, are rejected. IPv6 remains unsupported. Validation is deterministic and offline, without runtime URL parsing or DNS resolution; it does not prove a host exists or is reachable. Credentials, whitespace, backslashes, control escapes, relative paths and non-HTTP(S) schemes are rejected. English is optional; public Thai fallback remains. Enums are exact/case-sensitive. Events have no end-date/order columns and do not support overnight/multi-day ranges.

IDs follow `[A-Za-z0-9][A-Za-z0-9_-]{0,99}`. Create generates `PROD-<UUID>` / `EVT-<UUID>` and checks uniqueness under lock without retrying a collision. Duplicate stored identities or unknown stored statuses fail closed. Missing/blank/duplicate/case-conflicting headers fail preflight; no schema repair is performed.

Example update payload: `{ "product_id": "PROD-example", "expected_revision": "r1-<64 lowercase hex characters from detail>", "price_range": "150–300 THB" }`.

## Responses, revision, audit

Success is `{ok:true,data:{...},message:"success"}`. List items and mutation data contain ID, status, revision, timestamps, Thai name/title and category/type. Detail contains ID, status, revision, timestamps and `content` with exactly the delivered editable fields (name/title and category/type appear inside content, not again at top level). Mutations add `audit_status: "recorded" | "unconfirmed"`. Unknown/private columns are not returned.

Revision is `r1-` plus SHA-256 of UTF-8 JSON `[entityType, 1, [fieldName, type, value], ...]` in fixed order (ID, every editable field, status). It includes numeric/boolean types, uses ISO UTC for stored Date objects, and never uses locale serialization. Timestamps/unrelated columns are excluded. Every update/delete compares against a fresh under-lock read. Changed-then-restored content can have the same hash (ABA); this is content concurrency, not edit history. Manual Sheet edits do not cooperate with the script lock.

Audit uses existing M7 `activity_logs` columns and uppercase actions: `CREATE`, `UPDATE`, `PUBLISH`, `HIDE`, `ARCHIVE`, `DELETE`, `RESTORE`, with entity type `product` or `event`. It writes `audit_id`, `actor_admin_id`, `occurred_at`, aliases `log_id`, `admin_id`, `created_at`, and entity ID. Description contains only resulting status/revision. No payloads/tokens/secrets are logged. Auth/validation/conflict failures create no mutation audit. Audit append/read-back is attempted once after entity verification. An audit warning requires operator reconciliation, not a repeated mutation.

## Failure and cache behavior

| Condition | Result |
|---|---|
| Authentication/role failure | `UNAUTHORIZED` / `FORBIDDEN`, no mutation |
| Invalid input/reference | `VALIDATION_ERROR`, no mutation |
| Missing target | `NOT_FOUND` |
| Stale revision | `CONFLICT`, no mutation/audit |
| Invalid lifecycle | `INVALID_TRANSITION` |
| Generated ID collision | `DUPLICATE_ID`, no retry |
| Schema/format/lock/cache invalidation preflight failure | Safe `SERVER_ERROR`, no entity mutation |
| Entity write attempted but write/flush/read-back throws or differs | `OUTCOME_UNKNOWN`, entity ID, `retryable:false`; retain actual row, no rollback/retry or success audit |
| Verified entity, audit append/read-back failure | Success with `audit_status:"unconfirmed"` |
| Lock release throws | Preserve the known operation result |
| Response lost | Browser result unknown; reconcile via protected reads |

Sheets has no transaction across entity and audit rows. No row is cleared/deleted to compensate for an uncertain result. All errors use safe fixed messages.

`ContentCacheService` adds a generation to actual Product/Event list/detail, Home and Search keys; existing Place epoch dependencies remain. Under the write lock, verify generation removal before writing. While absent, public readers acquire the same lock to establish a UUID generation (21,600-second TTL), or bypass caching. Existing 300-second response caches become unreachable after mutation/eviction; old in-flight readers can populate only unreachable old keys. No default namespace is reused and no Script Property changes are needed. Cache read/initialization failures preserve uncached public reads. Failure to verify invalidation aborts before content mutation. Either domain mutation deliberately invalidates both domains and both aggregates; unrelated public services remain unchanged.

## Reconciliation

Success includes entity ID, status, revision, timestamps and audit status. Unknown outcomes include entity ID and `retryable: false`. After a lost response, refresh Admin list/detail and compare content; never automatically resubmit. A lost create response may lose the server-generated ID, so search the Admin list using the submitted title/name and inspect candidate records. There is no exactly-once request ledger. Manual Sheet edits are outside cooperative locking.

Phase B implements editors, validation feedback, lifecycle controls, revision-conflict handling, audit warnings and explicit reconciliation. Existing preparation messages remain. Remote schema/format readiness and real-Sheets integration QA remain human release gates; local tests do not prove remote formats/deployment state.
